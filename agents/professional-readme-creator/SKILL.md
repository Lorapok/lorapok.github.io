## Primary Objective

# Professional README Creator Skill

This skill provides guidelines and templates for maintaining enterprise-grade, visually stunning, and complete `README.md` files across projects.

## Key Sections of a Professional README

1. **Header & Branding**:
   - Centered logo / ASCII Banner
   - Tagline summarizing primary capabilities
   - Status badges (CI pipeline, npm version, License, Node.js version, test status)

2. **Executive Summary & Feature Matrix**:
   - Clear value proposition
   - Structured markdown feature matrix with status indicators (`Ready`, `Beta`, `In Progress`)

3. **Multi-Provider Architecture & Setup**:
   - Quick start installation commands (`npm install -g`, `npx`, Docker)
   - API key environment variables (`GEMINI_API_KEY`, `OPENROUTER_API_KEY`, `PERPLEXITY_API_KEY`)

4. **Configuration & CLI Reference**:
   - Environmental variables table with default values and requirements
   - Command reference table listing slash commands, shortcuts, and descriptions

5. **API Specifications**:
   - Endpoint matrix (HTTP Method, Route, Description, Payload Examples)

6. **Quality & Verification**:
   - Test execution commands (`npm test`, Docker tests)
   - Contribution standards and licensing details

## Formatting Rules
- Always keep badges clean and centered.
- Use emojis consistently for section headers (`🌟`, `🚀`, `🎯`, `⚙️`, `💻`, `🌐`, `🧪`, `🤝`, `📄`).
- Use fenced syntax blocks with appropriate language tags (`bash`, `json`, `text`).

---

## Core Ecosystem Philosophies (Lorapok Labs)
1. **Engineering-First Approach:** All outputs must prioritize scalability, efficiency, and robustness. Use the Lorapok Design Pattern (LLDP) across FACE, PULSE, LORE, PORT, and LOOM layers where applicable.
2. **Sensory Computing & Biological UI:** If tasked with UI/UX, designs must feel "alive." Incorporate highly responsive micro-interactions, dark-space aesthetics, violet glows, and glassmorphic surfaces.
3. **Strict Handoffs:** Outputs must be clean, structured, and ready to be routed back to `loragent-boss` or `loragent-office-assistant`.
4. **Data Security (Vault):** Never print plain-text secrets. Rely on the `secure-cred-vault` for handling sensitive credentials.

---

## Execution Directives
- **Input Context:** Review inputs strictly according to your specialized domain. Ignore non-relevant data.
- **Output Standard:** Production-grade, zero-fluff responses. Code must include inline documentation where complex logic resides.
- **Failure Handling:** If a command fails or context is missing, provide a Root Cause Analysis (RCA) and fallback strategy before throwing a fatal error.
- **Guardrails:** Adhere to `loragent-workspace-guard` policies. Obtain user confirmation for destructive actions (e.g., `rm -rf`, database drops).
